We can compile ex01.java with compiler option -verbose by executing:
```
dotnet run -verbose .\JavaEx\ex01.java
```

- What is the purpose of the class label for class B? 

It is a label representing the class descriptor of class B, which has the vtable of methods. It is used so we can do dynamic dispatching, i.e. virtual method calls.

- What is the index of field B.i in instance objects of type B? 
By reading the class environment we observe:
```
B (L3_class_B): A:
Field Environment with next offset 3:
  A.i:int -> 1
  B.i:int -> 2
```
This means that the index of field B.i in instance objects of type B is `2`.

- How many bytecode instructions are generated?

The compiled program has 74 bytecode instructions.

3. Compile ex02.java using the compiler option -debug. Look at the micro-

- Explain the bytecode instructions used to create an instance object for the main method, load command line arguments and call the main method.

Below are the bytecode instructions used to create an instance object for the main method, loading command line arguments and calling the main method:
```fsharp
0: PUSHLAB L10_class_Main // Pushes the label of the main class, i.e. the address of its class descriptor
2: HEAPALLOC 4 1          // ALlocates the object on the heap leaving the pointer 
5: HEAPCOPY 1             // Moves the address of the classdescriptor sitting on the stack into the heap allocated object, so it knows its vtable
7: LDARGS 0               // Loads 0 arguments
9: VCALL 1 0              // Virtual method call to main method found at vtable index 0 in the main object, and the amount of arguments which is 1 (since this is passed)
12: STOP                  // Stops the exxecution after main method finishes
CLASSDECS...
```

- Explain what code line addresses contains the class descriptor, that is, virtual method table, for class B.

As seen below:
```fsharp
LABEL L8_class_B
   284: LabelAddr L4_f
   285: LabelAddr L5_fSuper
   286: LabelAddr L6_i2Super
   287: LabelAddr L7_g
```
It is the lines `284-287` that contain it.

- Explain what code line addresses contain the code for method f() in class B.

From the vtable we can read that the method `f()` has `LabelAddr` `L4_f`, which starts at line `288` to `300`:
```fsharp
LABEL L4_f
   288: GETBP
   289: CSTI 0
   291: ADD
   292: STACKADDR
   293: LDD
   294: CSTI 3
   296: HEAPADDR
   297: LDD
   298: RET 1
   300: INCSP 0
```

- Explain the bytecode instructions for method f() in class B. For instance, what index in the instance object is used to access field this.i2.

Below the byte code is explained:

```fsharp
LABEL L4_f
   GETBP; CSTI 0; ADD // Compute address of "this
   292: STACKADDR     // Get the memory address of "this" on the stack
   293: LDD           // Load the pointer to "this"
   294: CSTI 3        // Offset 3, so the index used to access this.i2 is 3
   296: HEAPADDR      // Compute the address of this.i2     
   297: LDD           // Load the the value of this.i2
   298: RET 1         // Returns the value this.i2
   300: INCSP 0       // Cleans up the stack, in this case we do no work
```
